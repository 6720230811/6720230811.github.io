# S6 — 性能与降级 + 验收对照

## 做了什么

### 1. 合并 draw call（`floor.ts`）

- **门洞实例化**：原来每道门 4–6 个独立 Mesh（门楣 / 门套左右立框 + 门头 / 拱券），十几道门就是
  六十多个 draw call 和六十多份 BoxGeometry。现在只把变换记成一张表，最后按材质各合成一个
  `InstancedMesh`（共用 1×1×1 立方体，靠矩阵给出位置 / 尺寸 / 转角）。拱券几何按「跨度|矢高」
  缓存，尺寸相同的共用一份。
  顺手修了一处旧问题：拱券门原来会叠两组立框（0–3.4 m 和 0–2.35 m 各一组，互相穿模 z-fighting），
  现在只留一路。
- **地面 / 天花**：原来每块地面一个独立 PlaneGeometry + 一份克隆贴图（克隆贴图在 GPU 上是各占
  一份显存的）。现在共用一张 1×1 plane 靠 scale 撑开，材质按「分区 + 重复次数」缓存 ——
  长廊几十块地面最后只落两三种材质。
- **挂画光晕**：原来每个挂画位克隆一份材质（70 多份）。悬停只有「常态 / 指着」两种状态，
  现在只留两份共享材质，悬停时整块换 `material` 引用；光晕 / 画布 / 展签共用同一张面片几何。
- 沿用之前已做好的：墙 / 踢脚 / 灯槽 InstancedMesh（S2）、缩略图先行 + 走近 14 m 换原图（S4）。

### 2. 移动端画质档 + 低性能自动降级（`floor.ts` + `index.ts`）

- **低配起步**：`isLowPower()`（粗指针 = 手机 / 平板，或 CPU ≤ 4 核）→ 像素比封顶 1.5、
  真实作品灯从 6 盏减到 3 盏。
- **看门狗**：纹理挂完之后开始采样帧间隔，连续 45 帧（约 2 秒）低于 26 fps 就动手 ——
  第一步先把像素比降到 1.0（温和），还慢就 `stop()` + `degrade()` 退回网格，复用现成的
  `#gal-fallback` 提示条。切后台 / 恢复的那几帧（间隔 > 500 ms）不计，网格模式不看。
- **触屏细节**：点按误判阈值从 6 px 放宽到 14 px（手指抖得多）；首次提示在触屏上换成
  触屏文案（「滑动看向，点地面走过去…」），不提 WASD 和 R 键。

### 3. 渲染基准对照设计规格（十五节）

- `toneMappingExposure` 0.95 → **0.90**；背景 `#D8D4CC` → **#191D20**；雾 `#D8D4CC / 0.012` →
  **#202528 / 0.008**（馆外是夜色，入口暖光才有戏剧性 —— 规格点名「不要用过亮的浅灰背景」）。
- 材质：墙 roughness 0.92、地面 0.74，`envMapIntensity` 统一 0.45（之前 0.6 / 0.4），与规格的
  材质基准一致。

### 4. 移动端 HUD（`gallery.css`）

新增 `max-width: 640px` 一档：画布高度收到 min(58vh, 420px)、小地图 6.5rem、按钮 / 章节胶囊
收一号、信息卡上移让开按钮排；**毛玻璃（backdrop-filter）在窄屏全部换成实色** —— 手机上
backdrop-filter 是帧率杀手。

### 5. 其它

- 修了一处泄漏：地面贴图 `clone()` 出来的纹理现在也进了 `track()`，`dispose()` 时会释放。
- `floor.ts` 源文件里混进过一个字面 NUL 字符（展签缓存 key 的分隔符，把文件变成「二进制」、
  grep 搜不了），换成了空格。

## 自测结果

`npm run check`：**0 errors / 0 warnings / 3 hints**（三条都是旧的无用变量提示）。`npm run build`：通过。

无头浏览器（playwright + 本机 chromium）：

- 本沙箱**当前没有任何可用的 WebGL**（逐组试过 swiftshader / EGL / llvmpipe 全套参数，
  `getContext('webgl2')` 都是 null；S5 时还能跑 3D 的环境现在跑不了了，用 HEAD 提交做对照
  也一样退网格 —— 是环境问题，不是改动引入的）。所以这轮实际验证到的是：
  - **桌面 + 移动视口下，「无 WebGL → 自动退网格 + 显示原因」全流程正常**，0 console errors，
    移动端网格、降级提示条渲染正确（截图确认）；
  - 帧率看门狗本身无法在真 3D 下验证（沙箱里 3D 起不来），阈值（26 fps × 45 帧、
    先降分辨率再降级）是按保守值定的，**上真机后值得盯一眼**；
  - 几何重构（门洞实例化 / 地面天花共用 plane / 光晕共享材质）只过了编译与构建，
    没能在真 3D 里目验 —— 改动是纯机械的「记变换 → 合批」，风险低，但建议你在能跑
    WebGL 的机器上开一次展厅确认没有视觉回归（重点看：门套四角、地面拼缝方向、悬停光晕）。
