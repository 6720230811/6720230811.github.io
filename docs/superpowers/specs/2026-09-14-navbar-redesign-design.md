# 顶栏改版 · 设计规格

- 日期：2026-09-14
- 状态：已实现并验证
- 需求原话：「换一个文案，还有不要出现个人信息，还有导航栏的设计也改的有创意一些」
  （附图是沉浸式首页首屏截图，画面上挂着一行「江西理工大学 · 中国 · 江西」和
  一行「计算机科学与技术 · 硕士研究生」）

同批改动里的首屏文案部分，记在 `2026-09-14-homepage-redesign-design.md` §15「第四轮」。

## 1. 目标与非目标

**目标**

1. 首屏**不再出现任何身份信息**（单位 / 地点 / 学位），并整批换掉首屏文案。
2. 顶栏从 Fuwari 的「居中一排链接」改成有自己性格的「眉批条」，且不牺牲既有的
   双语、明暗主题、可达性、无 JS 与减动效降级。
3. 不动导航项的数量、顺序、`href` 与 `aria-current` 语义 —— e2e 第 2 组与第 9 组
   的判据全靠它们（点导航是那套里唯一「真实客户端换页」的触发方式）。

**非目标**

- 不做顶栏透明化（首屏上悬一条玻璃条）。理由见 §5。
- 不改窄屏菜单面板的交互方式（仍是点击开合），只统一它的视觉语言。
- 不改任何页面的内容与路由，不动 `profile` 数据 schema。

## 2. 现状：四条影响设计的事实

| # | 事实 | 出处 | 对设计的影响 |

## 3. 版面决策：两端分居，不居中

```
左端   ◆ 站名 ┃ 访客时钟                     右端   01 关于 02 博客 03 画廊 04 友链
                                                  [搜索] [主题] [中/EN] [☰]
```

理由：居中会在**版心正中立一条对称轴**，而首屏这一版刻意在拆的就是那条轴
（见首页规格 §7「版面为什么不是一列」）。两端分居与首屏同构 —— 那边也是
「左刊头 / 右一句小字，两条小字分居两端」。

顺带解决了两件事：字标补上了「点回首页」（此前窄屏只能从菜单面板回去），
时钟与字标并排后也不再独占一个格子。

## 4. 三件机关

### ① 导航项的 01–05 编号（CSS 生成）

`data-no` 写在元素上，数字由 `.navbar__link::after { content: attr(data-no) }` 画出来，
再用 `order: -1` 排到文字左边（链接是 `inline-flex`，`::after` 本来是收尾的那个）。

**不能写进标签文本**：`textContent` 会变成「01首页」——读屏会把编号念出来，
e2e 第 2 组的判据也会红（见 §2 第 4 条）。`::before` 已经让给 hover / 当前项那层
底色了（`inset: 0` 的 btn-plain 底），所以编号只能用 `::after`。

窄屏菜单面板里的编号同源（`.nav-menu__link::before`），两边是同一套视觉。

### ② 当前项下面那条会滑动的细线

```html
<nav class="navbar__nav">
  <a class="navbar__link" data-no="01" aria-current="page">首页</a>
  …
  <span class="navbar__ink"></span>   <!-- 必须排在链接之后 -->
</nav>
```

位置与宽度由脚本量一次写进 `--nav-ink-x` / `--nav-ink-w`（`transition` 负责滑动）。

三个必须记住的点：

- **`<span>` 要排在链接之后**。链接自己是 `position: relative; z-index: 0`，
  `::before` 底色 `inset: 0` 铺满整条；指示线若排在前面、又不给更高的 `z-index`，
  会被那层底色整个盖住。
- **量的是「文字那一段」**，不是整条链接（链接左右各有 1.25rem 内边距）：
  所以 `x = link.offsetLeft + paddingLeft`、`width = offsetWidth − paddingLeft − paddingRight`。
  `offsetParent` 就是 `.navbar__nav`（它有 `position: relative`），坐标系天然对齐。
- **没量到之前不显示**（默认 `opacity: 0`）。在导航之外的页面（例如 `/admin`）没有
  `aria-current`，这条线就整个撤掉 —— 宁可没有，也不要指错地方。

### ③ 卡片下缘的滚动进度 + 已滚动态

`.navbar__progress` 是一条贴着卡片下缘的 2px 发丝线（`scaleX(--nav-p)`），
滚过 8px 才淡入；`.navbar--scrolled` 同时把卡片的阴影加深、边框色提亮，
做出「离开页顶了」的感觉。**只用阴影与边框色**表达抬升，理由见 §2 第 1 条。

不写 `transition` 在进度条上：这个值每帧都在变，加了只会变成「拖着走」。

## 5. 断点：768 → 1024

编号把每一项撑宽约 21px（两位等宽数字 + 0.5rem 间距），五项 **+107px**。
算下来 768px 视口需要约 **856px**：

```
字标 60 + 竖线 1 + 间距 14 + 时钟 ~70 + 间距 8 + 导航 462 + 间距 8 + 工具簇 190
+ 卡片内边距 32 + 两端间距 16 ≈ 856
```

原来的 768 断点只余几十像素，硬挤只能压字距。**把断点抬到 1024px**，
让 768–1023 这一段收进汉堡菜单 —— 那一段本来就是平板竖屏，收起来比挤着好看。

窄屏让位的是**时钟**而不是字标：字标是功能（回首页），时钟是装饰（访客城市 + 时间）。

## 6. 降级

| 条件 | 行为 |
|---|---|
| 无 JS | 编号照旧（CSS 生成）、当前项照旧有主色底与主色字（`[aria-current]` 那两条）；指示线与进度线**不出现**（默认 `opacity: 0`）。退化成「一版更克制的 Fuwari 顶栏」 |
| `prefers-reduced-motion: reduce` | 指示线不做滑动位移（`transition: none`），卡片不做过渡 |
| ≤ 1023px | 导航收进汉堡菜单、时钟与竖线让位、字标保留 |
| 不在导航里的页面（`/admin`） | 没有 `aria-current` → 指示线整个撤销（不是指到第一项） |
| 画廊 / 放映室沉浸模式 | 顶栏被既有规则整体隐藏（`body.is-immersive .navbar`），不受本次影响 |
| 打印 | 顶栏被既有 `@media print` 隐藏 |

## 7. 无障碍

- 编号是 **CSS 生成内容**：不进无障碍树，读屏只念标签文本。
- 字标是真 `<a>`，指向语言根（`/` 或 `/en/`）。
- 指示线、进度线、字标前那枚方块都是 `aria-hidden`；进度线还带 `pointer-events: none`。
- 导航项的 `aria-current="page"`、工具按钮的 `aria-label`、菜单按钮的
  `aria-expanded` / `aria-controls` 全部保持原样。
- 焦点环不变（`.navbar__link:focus-visible` 的 2px 主色描边）。

## 8. 顺手修掉的一个静默失效

窄屏菜单面板的「当前页高亮」原来挂在 `.nav-menu__link[aria-current]::before` 上，
但那条 `::before` **从来没有 `content`** —— 伪元素根本不会生成，所以那个高亮
一直没生效（宽屏看不出来，那边走的是另一套）。这次 `::before` 让给编号，
高亮改落在整条链接上（主色底 + 主色字），失效顺带修掉。

## 10. 首屏文案：把身份信息撤干净

| 位置 | 原 | 现 |
|---|---|---|
| 刊头小字 `.hh__eyebrow` | `profile.affiliation · profile.location`（江西理工大学 · 中国 · 江西） | 文案表 `home.eyebrow`（个人数字花园 / A personal digital garden） |
| 刊头右端 `.hh__kicker` | `profile.title`（计算机科学与技术 · 硕士研究生） | 文案表 `home.kicker`（笔记 · 照片 · 书签 / Notes · Photos · Bookmarks） |
| 右栏一句 | 写下来的笔记，拍下来的照片，/ 还有那些舍不得关掉的标签页。 | 写下来的东西，比记得住的更可靠。/ 所以想到的、看见的，都留在这里。 |
| `<meta name="description">` | `title + interests[:2]`（含学位） | 只留 `interests[:2]` |

**站名（`profile.name`）保留**：它是这个站的名字，也出现在 `<title>`、社交卡片与
侧栏里，不是「关于我」的信息。首屏的 `h1` 与顶栏字标用的都是它 —— 撤掉它，
刊头就没有抬头了。**要连它一起换掉是一行的事**（指向文案表里另一个 key 即可）。

`<meta name="description">` 那一条容易被忽略：页面撤干净了、搜索结果里还挂着
「计算机科学与技术 · 硕士研究生」，等于没撤。首页的 description 改成只取
研究方向（`大模型推理优化 · 分布式系统`），`<title>` 保持「站名 · 研究方向」。

实测：

| 项 | 实测 |
|---|---|

| 字标 | `adgo`，`href="/"`；与时钟同在 `.navbar__lead` |

| 监听唯一性 | `{binds:2, unbinds:1, measures:3}` —— 建比撤多一，即始终只有一份 scroll/resize 监听 |
| 首屏（未回归） | 三层位移 21.74 / 50.72 / 94.2（期望 21.7 / 50.7 / 94.2）；首屏 828 + 顶栏 72 = 900；首屏图 458.1 KB |

**这一轮踩到的两个坑，都是「改完必须回读」那一类**：

1. **同一文件并行 Edit 会静默丢改动**（本仓既有约定，见项目记忆）：`HomeHero.astro`
   的两处修改只落了第一处，第二处无声消失 —— 回读文件时才发现（文件 mtime 已更新、
   内容却是旧的）。
2. **`replace_all` 会把函数定义处一起改掉**：把 e2e 驱动里的 `reloadHome(cdp)`
   全量替换成 `reloadHomeFn(cdp)` 时，`async function reloadHome(cdp) {` 那条**定义**
   也被改了，而 `await run(..., reloadHome);` 这种**不带括号的裸引用**没被匹配到 ——
   脚本一跑就 `ReferenceError`（而且报在第一组之前，看起来像「什么都没跑」）。
   **重命名要连裸引用一起 grep**，不能只看带括号的调用点。
