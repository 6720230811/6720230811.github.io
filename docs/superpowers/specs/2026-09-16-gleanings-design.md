# 拾遗 / Gleanings —— 多来源聚合页设计（2026-09-16）

导航第 05 项，`/gleanings/`。把三类外部内容收进一页：我存的网页与工具、
GitHub star 的仓库、各站榜单的热点。另加三个轻量手工模块。

设计已获用户确认；本文是该刀的**唯一凭据** —— 改动越界没越界、以后怎么复跑，都看这里。

---

## 一、定位

全站现有五页都是**自产内容**：博客是我写的、画廊是我拍的、关于是我这个人。
拾遗是**第一个「他产内容」的目的地** —— 我收集的、别人做的。

因此它的版面语言定成 **索引柜**：顶上一条统计，下面若干抽屉，每个抽屉有自己的形态。
不套文章版心（那是博客的语言），也不做画册跨页（那是画廊的语言）。

一句话定位：**「外面捡回来的，留在这一页。」**

## 三、六个模块

| # | 模块 | 内容 | 形态 | 分组依据 | 数据来源 | 期 |
|---|---|---|---|---|---|---|
| 01 | 现在 Now | 最近在做什么、读什么 | 几行字 + 写下日期（裸区） | 不分 | 手工 | P1 |
| 02 | 收藏夹 | 我存的网页与工具 | 2 列卡片网格（卡片） | 主题词表 | 手工 | P1 |
| 03 | 仓库 | GitHub star | 紧凑列表（卡片） | 主题词表 | 抓取 | P1 |
| 04 | 雷达 | 各站榜单的热点 | 有序榜单（卡片） | **按来源** | 抓取 | P3 |
| 05 | 工具箱 | 我实际在用的工具 | 定义清单（裸区） | 用途词表 | 手工 | P2 |
| 06 | 眉批 | 别人说过的句子 | 引用卡（裸区） | 不分 | 手工 | P2 |

### 三条不可让步的组织原则

1. **主题词表由「收藏夹」与「仓库」共用**（受控 ASCII key + 双语显示名，
   写法沿用 `src/data/taxonomy.ts` / `src/lib/taxonomy.ts` 那一套）。
   共用是为了让整合层的筛选有统一维度，且加一个主题只改一处。
   雷达不参与 —— 它按来源分组，来源天生就是分好的组。

2. **卡片与裸区交替**。三个大件（收藏夹 / 仓库 / 雷达）用 `Section` 白卡片，
   三个轻件（现在 / 工具箱 / 眉批）用**裸区块**（只有细分隔线 + 小标题）。
   六张白卡片纵向堆叠会糊成一堵墙；交替才有「索引柜」的节奏。

3. **不强行统一分类，统一发生在筛选层**。各模块的分组维度本来就不同，
   硬套一套标签只会得到三组互相别扭的结果。

### 与初版设计的两处修订（基于真实数据）

**① 仓库从「只展示精选」改为「全量分组展示」。**

初版设想是抓全量、只渲染精选，理由是「这一页是我替你拣过了」。
拿到真实数据后改了：你的 57 个 star **没有一个是无关的**（全是 Agent Skill
生态、AI 应用、LLM 学习资料），隐藏其中 45 个反而更差 ——
一个需要天天维护「谁被隐藏了」的页面，很快就会没人维护。

改为：**全量按主题分组展示**，`featured` 只影响**组内排序与视觉权重**，
不决定存亡。想突出某一条，写 `note`；有 note 的条目视觉更重。

**② `note` 缺省时回落仓库自述。**

`note`（「我为什么收它」）仍是这个模块的灵魂，但不强制。
没写的时候显示仓库自己的 description —— 那本来就是它的价值说明。
这样页面立刻是完整的，你可以只给真正在意的几条补批注。

## 四、数据层

### 4.1 文件清单与职责边界

| 文件 | 谁写 | 职责 |
|---|---|---|
| `src/data/gleanings/topics.ts` | 手工 | 主题词表（纯数据，零 import） |
| `src/data/gleanings/links.json` | **手工** | 收藏夹 |
| `src/data/gleanings/now.json` | **手工** | 现在 |
| `src/data/gleanings/stars.json` | **抓取脚本** | star 的客观事实（全量覆盖） |
| `src/data/gleanings/stars-curated.json` | **手工** | 我对 star 的判断（脚本从不碰） |
| `src/lib/gleanings.ts` | 手工 | schema、读取、合并、双语取名、断言 |

**这条边界是硬约束**：`collect.mjs` 只允许写 `stars.json`。
手工文件永远不进抓取脚本的写入路径 —— 一旦脚本有权覆盖手工文件，
某天源改版就会把你写的东西擦掉。

### 4.2 字段定义

`stars.json`（生成，脚本全量覆盖）

```json
{
  "source": "github",
  "owner": "6720230811",
  "fetchedAt": "2026-09-16T02:12:24Z",
  "repos": [
    {
      "fullName": "unclecode/crawl4ai",
      "url": "https://github.com/unclecode/crawl4ai",
      "description": "…",
      "language": "Python",
      "stars": 83597,
      "forks": 1234,
      "pushedAt": "2026-09-01T…",
      "starredAt": "2026-08-…",
      "archived": false
    }
  ]
}
```

字段一律从 API 取**客观值**，不含任何我的判断 ——
判断全在 `stars-curated.json`。这样脚本可以放心地整份覆盖。

`stars-curated.json`（手工，覆盖层）

```json
{
  "repos": {
    "unclecode/crawl4ai": { "topic": "crawl" },
    "paperless-ngx/paperless-ngx": {
      "topic": "selfhost",
      "featured": true,
      "note": { "zh": "自托管文档归档，扫描件进来自动 OCR。" }
    }
  }
}
```

一个仓库一个对象，**只写与默认值不同的字段**（默认：无主题 → 未归类组，
不精选，无注）。这样这个文件可以很短。

`links.json`（手工）

```json
{
  "links": [
    {
      "url": "https://…",
      "title": "标题（保持原文，不翻译）",
      "note": { "zh": "为什么收它" },
      "topics": ["frontend"],
      "addedAt": "2026-09-10",
      "featured": false
    }
  ]
}
```

`url` 即主键（要求唯一）。`title` 与 `note` 都是**必填** ——
没有那句「为什么收它」的链接等于书签栏，不该进这一页。

`now.json`（手工）

```json
{
  "updatedAt": "2026-09-16",
  "items": [{ "zh": "在做拾遗页，把 star 与收藏收进站里。" }]
}
```

### 4.3 主题词表（P1 初版）

按真实 star 分布定，9 个：

| key | 中文 | 英文 | 说明 |
|---|---|---|---|
| `agent` | 智能体与 Skill | Agents & Skills | 你 star 里最大的一簇 |
| `llm` | 模型与训练 | Models & Training | |
| `ai-app` | AI 应用 | AI Apps | |
| `doc` | 文档与 OCR | Docs & OCR | |
| `crawl` | 抓取与语料 | Crawling & Corpora | |
| `selfhost` | 自托管与网络 | Self-hosting & Network | |
| `design` | 设计与前端 | Design & Frontend | |
| `vision` | 图像与视频 | Vision & Video | |
| `quant` | 量化与金融 | Quant & Finance | |

`order` 定索引顺序。**每个 key 都出页/出组（含 0 条的）** —— 与博客分类同一约定：
分类是信息架构，先于内容存在。

**未归类兜底**：`stars-curated.json` 里没有条目的仓库落进「未归类 / Unsorted」组。
**不隐藏、不报错** —— 你新 star 一个仓库，第二天它就会出现在这一组里等着被归类。
这是诚实的做法（没有东西被悄悄丢掉），代价是要防它膨胀：

> 未归类组**最多显示 12 条**，超出显示「还有 N 个未归类」+ 指向 GitHub 全量 star 页的出口链接。

### 4.4 双语策略（**刻意偏离 `friends.json`**）

`friends.json` 用 `{ "zh": [...], "en": [...] }` 两套并列数组 —— 手工量小，可行。

拾遗**不这么做**：57 个仓库要维护两份是不可能的，它会直接导致这个模块没人维护。
改为：

- **结构化字段共享一份**（url / 主题 / 日期 / 采集值）
- **人类可读的散文段（`note` / `now.items` / `title`）用 `{ zh, en? }`，`en` 缺失时回落 `zh`**

界面文案（模块名、统计条、空态）仍然走 i18n，中英各写一份，与全站一致。
条目标题保持原文**不翻译**（外站标题翻了反而找不到）。

## 五、展示与版式

页面自上而下：

```
[吸顶模块导航]        ← 现在 / 收藏夹 / 仓库，锚点跳转 + 滚动高亮
[页首：定位语 + 统计条]
────────────────────  ← 裸区分隔线（用 --c-border，不是 --c-border-soft）
[现在]                ← 裸区
────────────────────
[收藏夹]              ← Section 白卡片，2 列网格
[仓库]                ← Section 白卡片，分组紧凑列表
```

**分隔线必须用 `--c-border`**：`--c-border-soft`（`#eef0f2`）是给白卡片当描边的，
压在页面底色 `#f0f2f5` 上只差 2/255，等于没画。裸区没有白底托着，只能用前者。

**吸顶值**：`position: sticky; top: var(--nav-h)`（顶栏 `--nav-h: 4.5rem` 是 sticky 的），
`z-index` 低于顶栏的 30。**不引入任何「sticky + 按视口算高度」的组合** ——
那类坑这站已经踩过两次（文章页 `.toc`、画廊跨栏）。

**网格轨道一律 `minmax(0, 1fr)`**，不写 `1fr` —— 后者等价于 `minmax(auto, 1fr)`，
轨道里的长标题会把栅格撑破。

`Section` 已自带 `scroll-margin-top: calc(var(--nav-h) + 1rem)`，
锚点跳转不会被 sticky 顶栏盖住。裸区要自己补同一条。

### 每个模块的形态细节

- **现在**：3–5 行短句，行前一个小方块记号；末尾一行小字「写于 2026-09-16」。
- **收藏夹**：2 列卡片（窄屏 1 列）。每张：域名/站点名 + 标题 + 我的批注 + 主题胶囊。
  外链带 `external` 图标，整卡可点。
- **仓库**：按主题分组，组内 `featured` 优先、其余按 star 数降序。
  每行：语言色点 + `owner/name`（等宽）+ 一句话（我的注优先，否则仓库自述）+
  右侧 star 数与最后推送时间。语言色点用 GitHub 官方语言色，未知语言用中性灰。

## 六、数据管道与四道守卫

```
外部源 ──▶ 抓取脚本（CI，每天）──▶ stars.json ──▶ astro build ──▶ 静态页
手工 ─────────────────────────▶ *.json ────────┘
```

### 接进现有 CI（已核实，改动最小）

`deploy.yml` 现在用 `withastro/action@v6`，它内部就跑 `npm run build`
（= `astro build && pagefind --site dist`）。因此：

1. 加 `schedule` 触发（每天一次）
2. 在 action **之前**插一步 `node scripts/collect.mjs`
3. **不需要改权限** —— `permissions` 保持 `contents: read`
4. **不 commit 回仓库** —— 数据只在 CI 工作区里用，所以不污染 git log、
   也不需要 `contents: write`

**这里本来有个坑，绕过去了**：用 `GITHUB_TOKEN` 推送触发的 workflow
**不会连锁触发**别的 workflow（GitHub 防递归的设计）。若采用
「collect.yml 抓完 push → 期望 deploy.yml 自动跑」的方案，部署根本不会发生。
插在同一条 workflow 里就与这件事无关。

代价要认：本地构建看到的是**上次快照**。要刷新就在本地跑一次 `collect.mjs`。

### 四道守卫（命中任一条即**不写文件**）

1. 请求失败 / 非 200
2. 抓到 0 条
3. 条目数骤降（低于上次的 60%）
4. 写入前 zod 校验不过

失败时脚本以非零码退出、workflow 标红，但**站点照旧用旧快照部署**。

> 这类页面最常见的死法不是抓不到，而是**抓坏了把好数据擦掉** ——
> 源改版返回半截 HTML、或被限流返回空数组，一次覆盖就把积累全清了。
> 四道守卫换个说法就是：**宁可数据旧，不可数据烂。**

### 过期可见

`fetchedAt` 静态渲染成绝对日期（`<time datetime="…">2026-09-16</time>`），
不用 JS 算相对时间 —— 静态站的「3 小时前」在构建那一刻就冻住了，
页面久不重建就会说谎。绝对日期永远不说谎。

超过 7 天（构建时判断）加一个「可能已过期」徽章。**过期能被看见就不算烂，
藏着不说才是真烂。**

## 七、整合与交互

| 机制 | 做不做 | 说明 |
|---|---|---|
| 吸顶模块导航 | **做**（P1） | 六个模块一页很长，这是最要紧的一条；锚点跳转 + 滚动高亮当前 |
| 统计条 | **做**（P1） | 条数全从数据现算，加内容不用回来改文案 |
| 主题筛选 | 视量而定（P4） | **条目总数 > 40 才做**，否则是过度设计 |
| 统一搜索 | **做，但不是「零改动」** | ⚠️ **本节原判有错，已改**：pagefind 只索引**带 `data-pagefind-body` 的文档**，而全站此前只有 `PostLayout` 带了它。实测加页后索引数卡在 9 页不动、拾遗页搜不到。**必须在 `GleaningPage.astro` 的 `.gl-page` 上显式加这个属性**（加了之后索引 9 → 11） |
| 外链语义 | 做 | 一律 `target="_blank" rel="noopener noreferrer"` + 外链图标 |
| 交叉引用（同一 URL 既是收藏又是仓库） | **不做** | 只保证 `url` 唯一；将来想查再说 |
| 双语 | 做 | 界面走 i18n，条目内容不翻译 |

**模块导航的滚动高亮**：`IntersectionObserver` 观察各模块，
在导航上标 `aria-current="true"`。**纯渐进增强** —— 无 JS 时它就是一排锚点链接，
照样能用。绑定走 `astro:page-load`（模块顶层只跑一次，换页后新 DOM 没人接管 ——
本仓在搜索按钮与宠物上栽过两次）。

## 十一、实现期发现并修掉的问题（规格原判有误的地方）

写在最后是因为这几条**都是「代码看着对、构建也绿」的问题**，
靠跑起来量才露出来。以后复盘别只看这一节，看它背后的判据。

1. **搜索不是「零改动」。** §七 原写「内容都在 HTML 里，会被 pagefind 索引，零改动」——
   错的。pagefind **只索引带 `data-pagefind-body` 的文档**，全站此前只有 `PostLayout` 带它。
   实测加页后索引数**纹丝不动卡在 9**。修法：给 `.gl-page` 加这个属性 → 索引 9 → 11。
   守卫落在 **e2e 里真打字搜索**（搜 `OCRmyPDF` / `PaddleOCR`，断言结果里有 `/gleanings/`），
   不是断言产物里有没有那个属性。

2. **`.gl-repo` 只有 4 条轨道，而「已归档」标记是第 5 个网格项。**
   快照里 `archived` 全是 `false` → 这段模板从没渲染过，也就从没被验过。
   量出来的后果：**行高 33.9 → 64.5**，星标日期被自动排布顶到第二行。
   修法：名字与标记包进 `.gl-repo__head`（`display:flex` + `min-width:0`），
   标记在语义上本来就是名字的注记，不是独立一列。
   守卫落在 e2e：**把标记插进真 DOM 再量行高**（1440 与 640 各一次），
   因为数据里永远没有这一条，不逼它就永远验不到。

3. **窄屏仓库行本来就在掉一行。** 48rem 断点只给 `.gl-repo__blurb` 写了
   `grid-column: 2 / -1`，于是它被显式落到第 2 行，而**自动排布的游标就停在它后面** ——
   DOM 里排在 blurb 之后的星标日期只能接着排到**第 3 行**。
   实测 640px 下每行 **100.1px**（应为 ~67px），星标那一格的宽度被算成 **0px**，
   57 行白多出近 2000px 页面高度。
   修法：断点里**四件都显式写出行列**。修完 **100.1 → 69.5**。
   守卫落在 e2e：每个宽度都断言「星标日期与名字齐平」。

4. **`.gl-nav` 的吸顶偏移是写死的 `var(--nav-h)`，而顶栏高度随断点变。**
   两边对不上就会在顶栏与导航之间裂一条缝。1440 全绿证明不了窄屏 ——
   所以 e2e 在 1440 / 800 / 640 下**各滚到吸住位置量一次**导航顶边 vs 顶栏底边。

5. **仓库从「只展示精选」改为「全量分组展示」** —— 这条是设计期就被数据推翻的，
   记在 §一①，此处不重复。它和上面 1～4 的区别是：那四条是**实现期**才暴露的。

6. **pagefind 会把 `<nav>` 整块当站内样板剥掉，零词的页面整个被丢弃。**
   §十一① 那条修完只走到「9 → 11」，拆成两条路由后**纹丝不动**。

   排查过程（`D:/homepage/.pfx-*` 下做过五组对照）：同一页
   `<div data-pagefind-body><p>…46 个词…</p></div>` 正常收进；
   把同样的词包进 `<nav>` → **0 词**；`<header>`/`<div>`/`<p>` 都收得进。
   更关键的是：**词数为 0 的文档不是「搜不到」，是整页不进索引** ——
   把四个带标记的拾遗页单独喂给 pagefind，只收进 2 页（内容页）。

   命门在于：总览页的正文（`.gl-page`）整个只有一个 `<nav class="gl-idx">`，
   而 `data-pagefind-body` 挂在它的外层 —— 标记了，但里面**一个可索引的词都没有**。

   修法两条叠在一起：
   - 给刊头 `GleaningHero.astro` 的根节点**也**挂一个 `data-pagefind-body`。
     刊头渲染在 `.page` **之外**（BaseLayout 的 `<slot name="hero" />`），
     跟着 `.gl-page` 是盖不住它的。一页里多个可索引区是**并集**（实测过）。
   - 顺带这条本来也该这么做：刊头那句定位、三个统计、「现在」三条是**真内容**，
     不是装饰 —— 「他最近在翻什么」正该落到这一页。

   修完 **11 → 13**（9 篇文章 + 4 条拾遗页），e2e 的判据是
   `dist/pagefind/pagefind-entry.json` 里的页数 `>= 13`，
   不是断言产物里有没有那个属性。

## 十二、第二轮修订（页首上横幅、拆两页、拆掉胶囊导航）

**来由**：第一版上线前用户看了三张图，三条意见 ——

1. 页首那块（定位语 + 统计 +「现在」）「不要单独写成一项」，**直接放进横幅那张图的背景里**；
2. 白色圆角胶囊导航「显示太丑了」；
3. 「不要把所有信息放在一页，页面太长」。

用户另外选定的粒度：拆页 = **总览 + 一条内容页（页内标签切换）**；
仓库长度 = **双列与折叠都做**。

### 12.1 页首搬上横幅（`BaseLayout` 新增 `hero="panel"`）

`hero` 此前只有 `banner | immersive | backdrop | none` 四档。新增第五档 `panel`：

| | `.hero`（装饰档） | `.hero--panel`（内容档） |
|---|---|---|
| 高度 | 设计值（`--banner-h`） | **内容的自然高度**（`height: auto`） |
| 文字色 | 跟随明暗主题 | **固定在亮的一侧**（同 `.hh`，理由同 §八①） |
| `margin-bottom` | 负值，让 `.page` 盖住底边 | `0`（底边下面就是正文，盖住会压到最后一行字） |
| `::after` 渐隐 | `40%` | 收到 `clamp(2rem, 4vw, 3rem)` 一条边 |
| `aria-hidden` | `true`（纯装饰） | 无（里面是字） |

版心对齐靠 `.hero__panel { max-width: var(--page-max); margin: 0 auto; padding: 0 1rem }`
与 `.page` 同一套值 —— 但**量的时候要量文字盒子**：
`.hero__panel` 自己带 1rem 内边距，拿它的**边框盒**去和正文左缘比会差整整 16px
（假失败，见 §12.5）。

### 12.2 胶囊导航 → 编号索引 `.gl-idx`

删掉 `.gl-nav` / `.gl-head` / `.gl-now` 三组样式与 `--gl-nav-h` / `--gl-offset` 两支变量。
换成与首页首屏同族的 `.gl-idx`：**细线在上、编号在前、没有底色也没有圆角**。

理由（也是「丑」的技术解释）：胶囊把整条横向空间占满，却只放三个小标签，右半截全是空的；
而编号索引天然是两列网格，把手下面还能挂三行预览，空间用满。

这排东西**在两处当两种角色**：
- 总览页 —— 入口。是 `<a href="/gleanings/all/#tab-repos">`，不是标签（面板还不存在，没得可切）。
- 内容页 —— 标签。`data-tab` + `aria-current`，点它切面板并把 hash 写进地址栏。
- 当前态**只换线与字色，不动字重**（字重一变标签宽度就变，切换时整排会左右跳一下）。

### 12.3 一条路由 → 两条

| 路由 | 内容 |
|---|---|
| `/gleanings/` | 刊头（`variant="overview"`）+ 带三行预览的编号把手 |
| `/gleanings/all/` | 刊头（`variant="section"`，一句说明）+ 两个面板 + 页尾再放一排把手 |

`/gleanings/all/` 里两个抽屉**共用一页**（收藏夹只有 8 条，单独开页太空）。
切换的状态写在**容器的 `data-ready`** 上，不写在各面板的类名上 —— 免得两处状态不同步。
**没有 JS 时两个面板都摊着**（`[data-gl-tabs][data-ready] .gl-panel:not([data-on])` 才隐藏）：
切换与折叠都只是「少滚几屏」的优化，**内容不可以丢**。

页尾那排把手**不带 `id`** —— `#tab-xxx` 一页里只能有一个。

### 12.4 仓库：宽屏双列 + 原生 `<details>` 抽屉

57 条铺一列约 4000px。宽屏（≥`64rem`）走两列，直接砍一半。
`<details>` 是原生的：键盘可达、`Ctrl+F` 找得到、**pagefind 也照样索引**
（它读构建出的 HTML，不是渲染后的可见性）。默认展开第一组，其余收起；
另给一个「全部展开 / 全部收起」按钮。

折叠后行宽变窄 → 仓库行换成两行排法。**窄屏与宽屏双列共用一条媒体查询的两个条件**
（`@media (max-width: 48rem), (min-width: 64rem)`）—— 写成一条，免得日后只改一处。

**开合指示排在标签前面，不推到行尾。** 第一版是 `margin-left: auto` 顶到右端，
结果 1100px 下标签在 `x=18`、箭头在 `x=1072`（行宽 1068）—— 裁到 2× 一看，
就是一粒浮在角落里的小三角，中间近千像素全空。这与用户嫌「丑」的那条白色胶囊
**是同一个毛病**：占满一条横向空间，却只用两头。而且这一行右上角没有别的东西
给它作伴（`.gl-idx` 的箭头旁边还有计数与预览），空得更明显。
排到前面之后整行是「▾ 组名 计数」一个紧凑簇。
给它**定宽 + 居中**：`▸` 与 `▾` 字面宽度不同，不定宽的话一开一合标签会左右跳一格。

判据落在 e2e：量 `.gl-drawer__chev` 与 `.gl-drawer__label` 的 `x`，要求
「箭头在标签左边、相距 < 24px、且箭头位于行宽的前 8%」——
「看着不对」这件事也得有断言守着，否则下次谁为了「对齐」又会把它顶回行尾。

### 12.5 这一轮被 e2e 抓出来的四条「假失败」

拆页之后 e2e 一度报 19 条失败，逐条量下来**四条都是判据过期，不是页面错**。
记在这里是因为它们全都有「看着像真 bug」的长相：

| 报出来的话 | 真相 |
|---|---|
| `刊头 120 vs 正文 136` | 拿 `.hero__panel` 的**边框盒**比 `.gl-page` 的边框盒。两行**文字**的左缘其实都在 136 |
| `期望 "repos"，实得 "repos/repos"` | 内容页有**两排**把手，共用状态 → 两个都标 `aria-current`。「当前是哪个」是集合，不是单值 |
| `横幅…应该 > 200px` | 内容页的刊头是 `section` 档，**本来就该矮**（实测 124–171px）。`>300` 那条判据属于总览页 |
| `顶栏 72px vs --nav-h=4.5rem` | `getPropertyValue('--nav-h')` 原样回 `"4.5rem"`，`parseFloat` 得 4.5。**自定义属性不会被解析成 px**，得挂探针元素去算 |

四条修完 **214/214 全绿**（明暗各一遍）。第 1 条顺手把「两排把手都标了吗」单列成
`currentRows` —— 去重会把「只有一排跟着走」这种半坏状态一起抹平。

**另有一条工具链的坑**：`evaluate(cdp, \`...\`)` 的第二个参数是模板字面量，
写在外面的注释**就在字符串里** —— 一个反引号就把它提前闭合，
报出来是「`SyntaxError: missing ) after argument list`」指向几百行外的一个 `(() => {`。
本轮在同一处掉了三次。改完先跑 `node --check`，它会直接把行号点出来。
